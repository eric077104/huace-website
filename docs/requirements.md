一、專案背景與目標

本專案為畫策管理顧問有限公司（HC 畫策整合行銷）官方網站改版與重建。網站應重新呈現公司目前及未來的服務定位，避免被理解為單純廣告代操、攝影工作室或一般社群接案公司。

網站主要目標：
1. 建立專業、可信任、具策略能力的品牌形象。
2. 清楚呈現畫策的服務能力、服務組合及合作模式。
3. 讓企業決策者能理解畫策可以解決的行銷與數位轉型問題。
4. 以網站獲得有效商業詢問、合作洽談及潛在客戶名單。
5. 建立可持續擴充的網站架構，日後可增加案例、文章、服務、產品或活動。
6. 網站應可由公司內部自行維護，不應每次更新內容都依賴工程師。

二、品牌定位

品牌：畫策整合行銷 HC
公司名稱：畫策管理顧問有限公司
英文品牌：HC / Huace

建議品牌定位：
Digital Growth Partner
企業的外部數位行銷與成長合作夥伴。

品牌核心主張：
讓行銷，成為企業的成長系統。

品牌說明：
畫策整合行銷整合行銷策略、品牌內容、數位廣告、影像製作與 AI 數位應用，協助企業從市場定位、內容溝通、流量獲取到營運流程優化，建立可持續運作、可衡量並能持續優化的行銷成長系統。

網站定位不應以「服務項目羅列」為主，而應以企業問題、解決方案及成果導向呈現。

三、主要客群

1. 中小企業負責人及企業決策者。
2. 希望建立品牌或改善品牌形象的企業。
3. 需要社群內容、影音及數位廣告的品牌。
4. 缺乏內部行銷團隊，希望外包或建立外部行銷團隊的企業。
5. 希望導入 AI、數位工具或自動化流程的企業。
6. 有行銷需求，但不清楚如何規劃、執行及衡量成果的企業。

六、首頁內容及模組需求

6.1 Hero 主視覺
目的：在首頁第一屏清楚呈現畫策定位及價值。
內容方向：
- 主標題：讓行銷，成為企業的成長系統。
- 副標題：整合策略、內容、成效與 AI 數位應用，協助企業建立更有效率、更具成效的行銷運作方式。
- CTA 1：了解我們的服務
- CTA 2：洽談合作

視覺方向：
- 具品牌辨識度。
- 不使用一般廣告公司常見的素材拼貼、廉價科技背景或過度裝飾。
- 可使用抽象視覺、動態文字、影像、視覺系統或品牌圖形。
- Hero 動態效果需注意效能、可讀性及行動裝置。

6.2 品牌定位區
說明畫策的角色及與一般單一服務供應商的差異。
內容應簡潔，避免冗長公司自述。
建議以「企業面臨的行銷問題」及「畫策如何整合解決」呈現。

6.3 四大核心服務
以四個核心領域呈現：
Strategy
Content
Performance
AI & Digital

每個區塊應包含：
- 名稱
- 一句核心說明
- 主要服務內容摘要
- 連結至詳細服務頁面或服務區塊

6.4 企業需求／問題情境
可呈現企業常見需求，例如：
- 品牌有產品，但缺乏有效的市場溝通。
- 社群持續更新，但無法帶來有效詢問。
- 有廣告預算，但缺乏策略及數據管理。
- 需要短影音，但無法建立持續製作流程。
- 行銷團隊人力有限，需要外部協作。
- 想導入 AI，但不知道從哪些流程開始。

6.5 整合服務／Solution
展示畫策可依企業需求組合服務，而非只銷售單項服務。
例如：
- Brand Growth：品牌策略＋內容＋媒體投放
- Content Engine：內容策略＋攝影＋短影音
- Performance Marketing：廣告策略＋素材＋數據優化
- AI Marketing Workflow：AI 工具＋流程設計＋教育訓練
上述名稱為方向性示例，實際方案及名稱可由品牌後續確認。

6.6 案例展示
案例應以實際專案為基礎。
每個案例可包含：
- 客戶／品牌名稱（取得公開授權後）
- 專案背景
- 問題或需求
- 畫策執行內容
- 成果或專案亮點
- 圖片／影片
- 服務標籤
- 案例詳細頁（可選）

若無法公開數據，應呈現工作內容、策略及成果描述，不得虛構數據或客戶成效。

6.7 合作流程
建議流程：
01｜需求了解
02｜策略與方向確認
03｜提案及專案規劃
04｜執行與製作
05｜數據回顧與優化

流程需可視化，並保持簡潔。

6.8 CTA
各頁應有清楚的下一步，例如：
- 洽談合作
- 讓我們了解您的需求
- 預約行銷諮詢
- 聯絡畫策

CTA 不應過度重複或使用大量不同名稱造成混淆。

七、About 頁面需求

About 頁應避免一般公司介紹形式的長篇文字。
內容建議：
1. 品牌定位及品牌主張。
2. 畫策的核心觀點及工作方式。
3. 服務能力如何整合。
4. 團隊及專業能力。
5. 專案合作流程。
6. CTA。

品牌文案方向：
畫策不只是提供單一行銷服務，而是依企業階段、商業目標及市場需求，整合策略、內容、媒體與數位工具，協助企業建立適合自身的行銷運作模式。

八、Services 頁面需求

Services 頁應具備服務總覽及服務詳細介紹能力。
每個服務領域需有：
- 服務名稱
- 服務定位
- 解決的問題
- 服務內容
- 適合對象
- 執行方式
- 可搭配的其他服務
- CTA

服務頁不應只列出大量名詞，應以企業需求及服務價值為主。

九、Contact 頁及表單

- 姓名（必填）
- 公司／品牌名稱
- 電子郵件（必填）
- 電話或 LINE（至少提供一種聯絡方式）
- 需求類型（可複選）
  - 行銷策略
  - 社群及內容
  - 攝影／影音
  - 數位廣告
  - AI／數位應用
  - 顧問／教育訓練
  - 其他
- 預算範圍（選填）
- 預計開始時間（選填）
- 需求說明
- 個資告知及同意（依適用法律及實際蒐集方式設計）

表單功能：
- 前端驗證
- 後端驗證
- 防垃圾訊息機制
- 提交成功訊息
- 提交失敗訊息
- 通知公司指定 Email
- 資料可存入後台或資料庫
- 可選擇串接 CRM、Google Sheets 或其他管理工具
- 表單送出後不得無提示地丟失使用者輸入內容

十、設計方向

整體風格：
- Minimal
- Modern
- Professional
- Strategic
- Premium
- Digital

設計原則：
1. 版面簡潔且有明確資訊階層。
2. 避免模板化的傳統數位行銷公司網站。
3. 避免過度使用卡片、圓角容器、漸層及裝飾性圖示。
4. 不應將所有服務都設計成相同的卡片排列。
5. 善用留白、字體、排版、比例及動態建立品牌感。
6. 強調內容閱讀及商業資訊清晰度。
7. 影像品質及影像呈現方式需符合攝影及影像製作品牌能力。
8. 動態效果應服務於資訊呈現，不應造成干擾。
9. 確保網站在手機上仍具有完整閱讀體驗。
10. 不使用過度浮誇或無法維護的動畫。

色彩及品牌設計：
- 以現有 HC 品牌識別及 Logo 為基礎。
- 請設計師提出完整色彩規範，包含主色、輔色、背景色、文字色、互動色及狀態色。
- 建立字體系統、字級、行高、間距及按鈕規範。
- 色彩及字體應具備足夠對比，符合基本無障礙要求。
- 不在未確認品牌色的情況下任意改造 Logo。

十一、Responsive Design

必須支援：
- Desktop
- Laptop
- Tablet
- Mobile

要求：
1. 使用 Responsive Layout，而非獨立製作固定尺寸版本。
2. 主要內容在手機上需重新安排版面。
3. 導覽列需有適當的手機導覽模式。
4. CTA 在手機上易於操作。
5. 表單在手機上可正常使用。
6. 影像、影片及背景元素需適應不同畫面比例。
7. 不應出現橫向溢出。
8. 手機端需測試主要瀏覽器及常見尺寸。

十二、技術及開發方向

工程師可依團隊熟悉的技術選擇提出方案，但需符合下列要求。

建議架構：
- 前端：Next.js 或其他適合 SEO 及效能的現代框架。
- TypeScript：建議使用。
- CSS：Tailwind CSS、CSS Modules 或其他可維護方案。
- CMS：可使用 Headless CMS 或適合企業自行管理的 CMS。
- Hosting：Cloudflare Workers。
- Form：具備安全驗證及通知功能的表單系統。
- Analytics：Google Analytics 4。
- Search：Google Search Console。
- Tracking：依需求串接 Meta Pixel、Google Ads Conversion Tracking 等。

技術要求：
1. 網站內容需具備可維護性。
2. 不應將所有文字、案例及服務內容硬編碼於單一程式檔。
3. 服務、案例、文章應可透過 CMS 或管理介面維護。
4. 網站架構需支援新增頁面及內容。
5. SEO Metadata 可個別設定。
6. 圖片需有適當的格式及壓縮。
7. 網站需支援 HTTPS。
8. 建置錯誤頁面及基本錯誤處理。
9. 不將 API Key、密碼或敏感設定暴露在前端。
10. 使用 Git 進行版本管理。
11. 開發、測試及正式環境需有適當區分。
12. 提供完整原始碼及部署說明。
13. 網站應避免依賴單一工程師才能維護的特殊架構。
14. 所有第三方服務、費用及帳號歸屬需在交付前說明。

十四、SEO 需求

基本 SEO：
1. 每頁可設定 Title。
2. 每頁可設定 Meta Description。
3. 每頁具備唯一 URL。
4. 支援 Canonical。
5. Sitemap.xml。
6. Robots.txt。
7. Open Graph。
8. 社群分享圖。
9. 結構化資料 Schema Markup，依適用內容加入 Organization、LocalBusiness（適用時）、Service、Article、Breadcrumb 等。
10. 圖片 Alt Text。
11. Heading 結構合理。
12. 內部連結。
13. 404 頁面。
14. 網站搬遷時，舊 URL 需規劃 301 Redirect。
15. 不應使用純圖片代替重要文字內容。
16. 確保搜尋引擎可正常索引主要內容。

SEO 內容方向：
- 整合行銷
- 數位行銷顧問
- 企業行銷策略
- 社群行銷
- 短影音行銷
- 商業攝影
- 影片製作
- 數位廣告
- AI 行銷
- AI 企業應用
以上需依實際市場、搜尋意圖及競爭分析制定內容策略，避免無差別堆砌關鍵字。

十六、效能及使用體驗

要求：
1. 圖片使用適當尺寸及格式，優先考慮 WebP／AVIF（依瀏覽器支援）。
2. 避免首頁載入過多大型影片及圖片。
3. 動態效果不得造成主要內容延遲顯示。
4. 盡量符合 Core Web Vitals 的良好標準。
5. 使用 Lazy Loading（適用於非首屏資源）。
6. 首屏主要內容及關鍵圖片需適當優化。
7. 避免大量不必要第三方 Script。
8. 網站需在常見手機及桌面瀏覽器保持穩定。

十七、資安及維護

1. HTTPS。
2. 表單防垃圾訊息。
3. 後端輸入驗證。
4. 基本防注入及常見安全風險處理。
5. CMS 權限控制。
6. 依實際架構安排更新及備份。
7. 不公開敏感資訊。
8. 第三方服務帳號需由公司持有或可移交。
9. 提供網站維護及更新方式。
10. 若涉及個資蒐集，需依實際法律要求處理隱私權政策及個資告知。
